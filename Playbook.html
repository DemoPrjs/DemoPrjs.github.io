How BMad Passes Context Between Agents — No Copy-Paste Needed

Step A

Agent saves output to a file

Every agent is instructed to save its work as a named file (e.g., prd.md) inside your project folder. The file lives on disk.

Step B

Next agent reads the file directly

In the next fresh context window, you tell the agent: "Read the file prd.md from this project directory." Claude Code uses its Read tool to open it — you never paste anything.

Step C

Agents build on each other

By Step 5, the Dev Agent reads prd.md + epics.md + architecture.md + ux-spec.md automatically. All context is inherited from disk — no manual handoff required.

New to BMad? Read this first

Each step runs in a fresh Claude Code context window. To open one: press Ctrl+N (or Cmd+N on Mac) in Claude Code, or click the + New Chat button. This keeps each agent's context clean and prevents confusion between roles. After each step, the agent saves a file to your project folder — the next agent will read it automatically.

Important — Set your working directory first

Before starting Step 1, make sure Claude Code is pointed at your Project6 folder. In Claude Code's terminal, run: cd /path/to/Project6. All agents will read and write files relative to this folder.

Phase 1 — Planning

PM Agent — Epics & User Stories

This step shows the audience how BMad structures work before any code is written. The agent reads prd.md — you don't need to paste anything.

Phase 2 — Solutioning

Architect Agent — Architecture Document

15 → 23 min
3
Architect Agent — Technical Architecture Document
The Architect Agent reads the PRD and Epics, then produces a technical architecture document. For this project (a single HTML file) it defines the file structure, CSS architecture, component breakdown, and how sections connect. This is a key demo step — it shows BMad produces professional documentation before any code is written.
8 min bmad-agent-architect
OPENOpen a new context window.
/bmad-agent-architect
PASTEThe agent will read prd.md and epics.md automatically.
You are the BMad Architect Agent. The planning documents for this project have been saved. Please read these files from the current project directory: 1. prd.md — the Product Requirements Document 2. epics.md — the Epics and User Stories summary Do not ask me to paste them — use your Read tool to open them directly. Once you have read both files, please create a technical architecture document for the project. PROJECT CONTEXT: This is a single-file HTML5 portal called "The Cloud" with NO external libraries. Everything — HTML structure, CSS, and any JavaScript interactions — lives in one file: TheCloud.html Please produce an Architecture Document (architecture.md) that covers: 1. TECHNOLOGY STACK - HTML5 (semantic structure) - CSS3 (embedded in <style> tag) — no frameworks - Vanilla JavaScript (if needed — only for minor interactions like mobile menu toggle) - No build tools, no package managers, no CDNs 2. FILE STRUCTURE - Single file: TheCloud.html - Internal structure: how the <head>, <style>, and <body> sections are organized 3. CSS ARCHITECTURE - CSS custom properties (variables) for the color palette and typography - Section naming conventions (e.g., .hero, .topics, .blog-posts) - Responsive design approach: flexbox/grid + media queries - Card component pattern (shared across topics and blog posts) 4. HTML COMPONENT BREAKDOWN Map each Epic to its HTML section: - EP-001 Navigation: <header> + <nav> - EP-002 Content Discovery: <section class="hero"> + <section class="topics"> - EP-003 Blog: <section class="blog-posts"> - EP-004 Onboarding: <section id="register"> + <form> - EP-005 Engagement: <section id="contact"> + <section class="about"> - EP-006 Infrastructure: <footer> + CSS variables + viewport meta 5. RESPONSIVE DESIGN STRATEGY - Breakpoints: 768px (tablet), 480px (mobile) - How the grid collapses from 3-col to 2-col to 1-col 6. PERFORMANCE CONSIDERATIONS - No HTTP requests (everything is embedded) - Minimal JavaScript (prefer CSS for transitions and hover states) 7. TRACEABILITY TABLE A table mapping each Epic ID → HTML section → CSS class → Acceptance criteria reference Save the complete document as: architecture.md
Output produced:
architecture.md Tech stack defined CSS architecture Epic → HTML mapping Responsive strategy
Quick check before moving on:

Tips for Demo Day — Avoid Common Mistakes

Always open a fresh window per step Using Ctrl+N / Cmd+N. Continuing in the same window contaminates the agent's context with the previous step's role — BMad agents work best with clean slates.
Confirm files are saved before moving on Type ls in the terminal after each step. If the file isn't there, ask the agent: "Please save your output to [filename] now."
Prompts are pre-written above Copy-paste the prompts directly. Do not retype during the demo — even one missing word ("epics.md" vs "epics") can confuse the agent.
If the Dev Agent runs over time After 8 minutes, type: "Please output the complete HTML file now — use placeholder sections for anything not yet finished." This gets you an openable file to show.
Show the artifacts, not just the HTML Open prd.md, epics.md, and architecture.md to the audience before opening the browser. The documents are the BMad story — they prove the methodology produced more than just code.
Highlight the "no copy-paste" moment When running Step 3 (Architect), point out to the audience that you only typed "read prd.md" — the agent found the file on its own. This is the core BMad demo talking point.
