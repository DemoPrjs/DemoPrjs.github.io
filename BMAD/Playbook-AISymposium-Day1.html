Phase 1 — Ideation

Brainstorming Agent — Define the Portal Scope

0 → 8 min
1
Brainstorming Agent — AI Symposium Feature Discovery
The Brainstorming Agent helps you think through the portal scope before writing requirements. It identifies all user types, key features, data fields, and flows — so nothing is missed in the PRD. Do this before writing any requirements.
8 min bmad-brainstorming
OPENOpen a brand-new Claude Code context window (Ctrl+N / Cmd+N)
/bmad-brainstorming
PASTECopy and paste this prompt. Press Enter.
I want to build an AI Symposium Portal — a professional event management web portal for AI training symposiums. Help me brainstorm the complete feature set. PORTAL PURPOSE: A single-file ReactJS-style HTML portal where participants can learn about AI symposiums, register for upcoming events, and access past recordings. Admins can manage events end-to-end. USER TYPES: 1. Guest visitor — browses upcoming and past symposiums 2. Registered participant — registers for events, requests recordings 3. Admin — creates, edits, and manages symposium events KNOWN FEATURES (expand on these): - Home page with featured upcoming symposium - Upcoming Symposiums list with registration - Past Symposiums archive with recording request form - Admin portal: create/edit/delete events - Contact Us form - Login page - AI chat widget EVENT DATA FIELDS (admin creates): - Event title, description, agenda - Date, time, location (city + venue) - Mode: In-Person / Virtual / Hybrid - Speaker name, speaker bio, speaker photo - Registration capacity, booked seats, available seats - Registration deadline - Tags/topics (AI, ML, LLM, GenAI, etc.) - Status: Draft / Published / Cancelled / Completed - Recording URL (post-event) - Contact person per event TEAM MEMBERS (show in Contact Us): - Puneet Gaur — puneet.gaur@yopmail.com - Mithun Davy — mithun.davy@yopmail.com - Alex William — alex.william@yopmail.com - Shiva Thyagaraj — shiva.thyagaraj@yopmail.com - Nagaraj Yanambakkam — nagaraj.yanambakkam@yopmail.com - Molly Mayers — molly.mayers@yopmail.com Please brainstorm: 1. Any features I might have missed 2. User flows for each user type 3. Admin panel sections and navigation 4. Chat widget behaviour 5. Registration flow (steps, confirmations) 6. Recording request flow Save your output as: brainstorm.md

Phase 1 — Planning

PM Agent — Create the Product Requirements Document

8 → 17 min
2
PM Agent — Product Requirements Document (PRD)
The PM Agent reads brainstorm.md and converts it into a structured PRD with acceptance criteria. Every downstream agent (Architect, UX, Dev) reads this file. Get this right — it is the source of truth.
9 min bmad-agent-pm
OPENOpen a brand-new Claude Code context window (Ctrl+N / Cmd+N)
/bmad-agent-pm
PASTECopy and paste this prompt. Press Enter.
You are the BMad PM Agent. Read the brainstorming document I produced earlier and create a complete PRD for the AI Symposium Portal. Read this file first: brainstorm.md (in current directory) PROJECT: AI Symposium Portal TYPE: Single-file HTML portal (React-style, no build tools, no external frameworks) AUDIENCE: IT professionals attending AI training symposiums PRD MUST INCLUDE: 1. Project Overview and Goals 2. Target Audience (3 user types with personas) 3. Portal Structure — 7 pages/views: a. Home — hero banner, featured upcoming symposium, stats, team intro b. Upcoming Symposiums — filterable card grid, register button c. Event Detail — full info + registration form (name, email, company, role, dietary) d. Past Symposiums — archive with recording request form e. Admin Portal — dashboard + create/edit/delete events (all 22 fields) f. Contact Us — team cards with 6 members and contact form g. Login — username/password form 4. Chat Widget — floating button, panel with AI-style responses about symposiums 5. Admin Event Fields (list all 22 fields with data types) 6. Technical Constraints: - Single HTML file (no React build, no npm install) - No external CSS frameworks (Tailwind, Bootstrap) - Vanilla JS for interactivity - Dark-first color theme - Must work in browser without server 7. Acceptance Criteria (one per feature) 8. Out of Scope Save as: prd.md
SAVEConfirm the file is saved
After the agent finishes, verify prd.md exists. If you see the PRD in chat but no file, say: "Please save to prd.md now."
Output produced:
prd.md 7 views defined 22 event fields Acceptance criteria
Quick check before moving on:
  • prd.md file exists in the project folder
  • All 7 portal views are documented
  • Admin event fields list has at least 15 fields
  • Technical constraint "single HTML file" is explicitly stated
  • Acceptance criteria cover registration, admin CRUD, and chat widget
Phase 2 — Design

UX Designer Agent — Create the UX Specification

17 → 29 min
3
UX Designer Agent — Layouts, Flows & Component Spec
The UX Designer Agent reads prd.md and produces a detailed layout and interaction specification. The Dev Agent uses this to implement the exact visual structure — without any guessing about layout, colours, or interactions.
12 min bmad-ux
OPENOpen a brand-new Claude Code context window (Ctrl+N / Cmd+N)
/bmad-ux
PASTECopy and paste this prompt. Press Enter.
You are the BMad UX Designer Agent. Read prd.md from the current directory and produce a complete UX specification for the AI Symposium Portal. Read: prd.md UX SPEC MUST COVER: 1. DESIGN SYSTEM - Font: Inter (via Google Fonts, weights 400–800) + system-ui fallback; monospace for labels/code - Full CSS token set (dark-first): --bg:#080D1A --bg2:#0D1526 --surface:#111827 --surface2:#1A2438 --surface3:#21304A --border:#2A3A54 --border2:#364A68 --text:#E2E8F4 --text2:#94A8C4 --text3:#5D7490 --accent:#10B981 --blue:#38BDF8 --purple:#A78BFA --orange:#FB923C --red:#F87171 --yellow:#FBBF24 - Gradient logo mark: 28×28px rounded square, linear-gradient(135deg, --accent, --blue) - Gradient hero heading: linear-gradient(120deg, --accent, --blue) text-fill effect - Light mode overrides under @media(prefers-color-scheme:light) + [data-theme="light"] 2. NAVIGATION - Top navbar: gradient logo mark + "AI Symposium" wordmark (accent colour on "Symposium") - Centre links: Home | Upcoming | Past | Contact - Right side (always visible, even when not logged in): "Admin ↗" subtle button — navigates to admin (shows login if unauthenticated) "Sign In" ghost button — navigates to login "Register Now" primary CTA button — navigates to Upcoming Symposiums - When logged in: replace Sign In + Register Now with "Logout (username)" button - Mobile: centre links collapse at <768px; logo + action buttons stay visible - Active state indicator on centre links 3. PAGE LAYOUTS — describe grid/flex layout for each: a. Home: hero banner (event title + countdown + CTA), stat row (total events / participants / speakers), featured event card, team section b. Upcoming Symposiums: search bar + filter chips (All / Virtual / In-Person / Hybrid), event card grid (3 columns), pagination c. Event Detail: event header (title, date, speaker photo), tab panel (About / Agenda / Speaker / Register), registration form d. Past Symposiums: archive grid, "Request Recording" button on each card, modal form e. Admin Portal: sidebar with 3 labelled groups: Overview: Dashboard | Create Symposium | Manage Events | Registrations | Recording Requests Management: Speakers | Email Campaigns (placeholder) Settings: Admin Users | System Config (placeholder) Dashboard: 4 KPI cards + recent events table with status pills Create form: 6 accordion sections (Basic Info, Date/Time & Location, Training Content, Seats & Registration, Speaker Information, Contact & Recording) f. Contact Us: 6 team member cards (photo placeholder, name, role, email), contact form g. Login: centered card (username, password, "Sign In" button) — no "Login" label 4. COMPONENTS - Event Card: colour-coded left band, status badge, title, date/time, location chip, speaker name, seats-remaining pill with progress bar, Register/View button - Registration Form: First Name, Last Name, Work Email, Company, Job Title, Phone (optional), Mode (In-Person/Virtual), "How did you hear about us?" dropdown, Special Requirements textarea, Submit - Recording Request Modal: name, email, reason textarea, submit - Recording Request Modal: name, email, reason textarea, submit - Chat Widget: floating button (bottom-right), slide-up panel (bot greeting + message input + send), rotating FAQ responses - Admin Event Form: 6 accordion sections — Basic Info, Schedule, Location, Speaker, Capacity, Media 5. INTERACTION STATES - Button hover/active states - Form validation (inline error messages) - Toast notifications for form success - Empty states (no events found) 6. RESPONSIVE BREAKPOINTS - Desktop (≥1024px): 3-column grid - Tablet (768–1023px): 2-column grid - Mobile (<768px): 1-column, stacked nav Save as: ux-spec.md

Phase 2 — Preview

Checkpoint Preview — Validate Your Design Before Building

29 → 36 min
4
Checkpoint Preview Agent — Wireframe from UX Spec
Before writing a single line of app code, the Checkpoint Preview agent generates a quick HTML wireframe directly from ux-spec.md. Open it in your browser to catch layout mistakes now — it's much faster to fix a spec than to fix built code.
7 min ⚠ no skill — paste direct
OPENOpen a brand-new Claude Code context window (Ctrl+N / Cmd+N)
Note: The bmad-checkpoint-preview skill is not installed in this BMad setup. Skip the slash command — just open a new context window and paste the prompt below directly. Claude will generate the wireframe without a skill wrapper.
PASTECopy and paste this prompt. Press Enter.
You are the BMad Checkpoint Preview Agent. Read ux-spec.md and prd.md from the current directory and generate an interactive HTML wireframe for the AI Symposium Portal. Read: ux-spec.md, prd.md Generate a SINGLE HTML FILE called: AISymposium-Wireframe.html The wireframe must: 1. Include a top navbar: gradient icon mark + "AI Symposium" wordmark; centre links: Home | Upcoming | Past | Contact; right side (always visible): Admin ↗ | Sign In | Register Now (primary CTA) 2. Show all 7 views using JavaScript toggle (show one view at a time) 3. Use the dark-first color palette from ux-spec.md (#080D1A background, #10B981 accent) 4. Include realistic sample data: - 3 upcoming events with title, date, location, speaker, seats - 2 past events with recording available / not available - Admin dashboard with event count stats 5. Make the registration form interactive (show success message on submit) 6. Show the chat widget button (bottom-right) with a slide-up panel 7. Include the admin event creation form with all 6 sections This is a design checkpoint — focus on layout correctness, not pixel-perfect styling. Save as: AISymposium-Wireframe.html
SAVEOpen in browser
After saving, open AISymposium-Wireframe.html in your browser. Click through every view. Check that the layout matches what you described in ux-spec.md. Note any discrepancies — update ux-spec.md if needed before Day 2.
