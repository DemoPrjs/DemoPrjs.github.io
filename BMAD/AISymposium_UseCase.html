Section 1

The Business Scenario

What problem are we solving? This is the context that makes the portal relevant — treat it as the client brief you'd receive on a real engagement.

Your team runs AI training symposiums — quarterly in-person and virtual events where professionals learn about AI, machine learning, and generative AI. Right now, everything is managed over email and spreadsheets.

You need a professional web portal that lets participants discover and register for upcoming events, revisit past sessions through recordings, and allows administrators to create and manage every detail of each symposium — all in one place.

📋

Manual Registration

Participants email to register. The team tracks seats on a spreadsheet. Overbooking happens.

🔗

No Recording Access

Past attendees struggle to find recordings. They email the contact person each time, creating back-and-forth.

🗂️

No Event Catalogue

There is no single place to browse upcoming and past symposiums with details like agenda, speakers, and topics.

🔒

Admin Work is Manual

Creating a new event means updating multiple documents, sending announcements, and manually tracking capacity.

Section 2

Who Uses the Portal

Three types of users interact with the portal, each with different access and goals.

Guest Visitor

Anyone browsing

Not logged in. Browses event information and decides whether to register. No account needed to view events.

Can do:
  • View home page and featured event
  • Browse all upcoming symposiums
  • See event details, agenda, and speaker
  • Browse past symposiums archive
  • Contact the team
  • Register for an event (via form)
Registered Participant

Event attendee

Submits the registration form for a specific event. Can request recordings of completed symposiums they attended.

Can do:
  • Everything a Guest can do
  • Fill out the registration form (name, email, company, role, dietary)
  • Request a recording via the Past Symposiums form
  • Use the AI chat widget for queries
Admin User

Event organiser

Logs in to the admin portal with a username and password. Full CRUD control over all symposium events and their data.

Can do:
  • Log in to the admin panel
  • Create new symposium events (22 fields)
  • Edit and update existing events
  • Delete or cancel events
  • Manage seat capacity and status
  • Add recording URLs post-event

What You Will Build — 7 Portal Views

The finished portal is a single HTML file with client-side view routing. No server, no build tools, no frameworks — just one file that opens in any browser.

View 1

Home

Hero banner, featured upcoming symposium card with countdown, stat counters (events, participants, speakers), and team introduction.

Public
View 2

Upcoming Symposiums

Filterable card grid of all published upcoming events. Each card shows date, mode, seats available, and a Register button.

Public
View 3

Event Detail

Full event info — agenda, speaker bio, location, capacity — plus the registration form (name, email, company, role, dietary needs).

Public
View 4

Past Symposiums

Archive of completed events. Each listing shows the contact person and a recording request form with a note sent by email.

Public
View 5

Admin Portal

Dashboard with event stats. Create, edit, and delete events across all 22 data fields. Seat and status management.

Admin only
View 6

Contact Us

Team member cards (6 people with names and email addresses). Contact form for general inquiries.

Public
View 7

Login

Username and password form for admin access. Grants entry to the Admin Portal view on successful authentication.

Auth gateway
