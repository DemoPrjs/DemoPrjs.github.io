Phase 3 — Architecture

Architect Agent — Technical Architecture Document

0 → 8 min
1
Architect Agent — Single-File Portal Architecture
The Architect Agent reads prd.md and ux-spec.md and decides how to structure the single-file portal — component tree, data model, JavaScript state management, and view routing. The Dev Agent follows this blueprint exactly.
8 min bmad-architecture
OPENOpen a brand-new Claude Code context window (Ctrl+N / Cmd+N)
/bmad-architecture
PASTECopy and paste this prompt. Press Enter.
You are the BMad Architect Agent. Read prd.md and ux-spec.md from the current directory and produce a complete technical architecture document for the AI Symposium Portal. Read: prd.md, ux-spec.md ARCHITECTURE MUST COVER: 1. FILE STRUCTURE - Single HTML file: AISymposium.html - Embedded <style> block (no external CSS) - Embedded <script> block (no external JS libraries) - No build tools, no npm, no node_modules 2. VIEW ROUTING - Client-side view switching via JavaScript - Views: home | upcoming | detail | past | admin | contact | login - URL hash routing: #home, #upcoming, #detail?id=X, #past, #admin, #contact, #login - Active nav link highlighting 3. DATA MODEL Define JavaScript objects for: - Event { id, title, description, date, time, location, mode, speakerName, speakerBio, capacity, bookedSeats, status, tags, recordingUrl, contactPerson, registrationDeadline } - Registration { eventId, name, email, company, role, dietary, registeredAt } - User { username, role: 'admin' | 'participant' } - ChatMessage { text, sender: 'user' | 'bot', timestamp } Include sample data: 3 upcoming events, 2 past events 4. COMPONENT ARCHITECTURE Describe each major function: - renderNavbar() - renderHome() - renderUpcoming(events) - renderEventDetail(event) - renderPast(events) - renderAdmin(section) - renderContact() - renderLogin() - renderChat() - navigate(view, params) 5. STATE MANAGEMENT - Global state object: { currentView, currentUser, events[], registrations[], chatMessages[] } - State mutation functions - localStorage persistence for login state 6. CSS ARCHITECTURE - Color token system (CSS custom properties) - Dark-first with light mode via prefers-color-scheme - Component class naming convention 7. SECURITY CONSIDERATIONS - Client-side only (no server) - Admin login: simple username/password check (hardcoded for demo) - XSS prevention: use textContent not innerHTML for user input Save as: architecture.md
SAVEConfirm the file is saved
After the agent finishes, verify architecture.md exists. Check it covers the data model and the component function list — the Dev Agent uses both directly.
Output produced:
architecture.md Data model Component tree State management
Quick check before moving on:
  • architecture.md exists in the project folder
  • Event data model has at least 15 fields
