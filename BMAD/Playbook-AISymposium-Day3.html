CONTEXT: - The portal is a single static HTML file (AISymposium.html) - Tests run against the file served locally via Python HTTP server or opened directly in a browser - Testing tool: Python Playwright (installed via UV) - No backend — all state is in-memory JavaScript TEST APPROACH MUST COVER: 1. Run Playwright Tests — Validate Every Portal Page
Follow these exact terminal commands to run the Playwright test suite. The browser will open and you will watch Playwright click through the portal automatically. Each command is explained so you understand what is being validated.
13 min Terminal
STEP 3.1Verify Playwright is installed
python3 -m playwright --version
✓ Expected: Version 1.x.x (any version). If "command not found", run: pip3 install pytest-playwright && python3 -m playwright install chromium
STEP 3.2Serve the portal on localhost (required for some browser security features)
Mac / Linux
# Run in a SEPARATE terminal — keep it running python3 -m http.server 8080 --directory .
Windows (CMD or PowerShell)
# Run in a SEPARATE terminal — keep it running python -m http.server 8080
✓ Expected: "Serving HTTP on 0.0.0.0 port 8080". Open http://localhost:8080/AISymposium.html in browser to confirm.
STEP 3.3Run the full test suite
Mac / Linux
# In main terminal (not the server one) cd /path/to/Project6 python3 -m pytest tests/test_portal.py -v --headed
Windows
# In main terminal (not the server one) cd C:\Users\YourName\Project6 python -m pytest tests/test_portal.py -v --headed
✓ Expected: Chromium opens, tests run one by one, browser clicks through the portal. Final line: "X passed, Y failed in Zs"
STEP 3.4Run only smoke tests first (fastest — 2 min)
python3 -m pytest tests/test_portal.py::test_portal_loads tests/test_portal.py::test_navbar_navigation tests/test_portal.py::test_home_page_content -v --headed
✓ Expected: 3 tests pass. If any fail, open the error output — it will say which element was not found.
STEP 3.5Run registration flow test
python3 -m pytest tests/test_portal.py::test_event_registration_form -v --headed -s
✓ Expected: Browser opens Upcoming page, clicks first event, fills the registration form, and a success message appears. "-s" shows print output so you can see what the test is doing.
STEP 3.6Run admin CRUD tests
python3 -m pytest tests/test_portal.py::test_admin_login_success tests/test_portal.py::test_admin_create_event tests/test_portal.py::test_admin_delete_event -v --headed -s
✓ Expected: Browser logs in with admin/admin123, navigates to Create Event, fills the form, submits, then deletes the event with a confirmation dialog.
STEP 3.7Run chat widget test
python3 -m pytest tests/test_portal.py::test_chat_widget -v --headed -s
✓ Expected: Chat button clicked, panel opens, message typed ("upcoming"), bot reply appears rendered as rich text (headings, bold, bullets). The chatbot calls the live AWS Bedrock API (https://mfobabs5n0.execute-api.us-east-2.amazonaws.com/dev/ask). The API response field is output_text and contains Markdown — the portal converts it to HTML before display. If the API is unreachable, FAQ fallback fires. A bot reply always appears either way.
STEP 3.8Run mobile responsiveness test
python3 -m pytest tests/test_portal.py::test_responsive_mobile -v --headed -s
✓ Expected: Browser resizes to 375px width. No horizontal scrollbar. Navbar collapses or stacks vertically.
STEP 3.9If a test fails — debug it with Playwright's interactive inspector
Mac / Linux
# Sets env var inline — opens inspector PWDEBUG=1 python3 -m pytest tests/test_portal.py::test_event_registration_form --headed
Windows CMD
# Set env var first, then run test set PWDEBUG=1 python -m pytest tests/test_portal.py::test_event_registration_form --headed
# Windows PowerShell alternative: $env:PWDEBUG=1; python -m pytest tests/test_portal.py::test_event_registration_form --headed
✓ Opens the Playwright Inspector. Use "Step Over" to advance one action at a time and see which selector failed. Copy the correct selector from DevTools and update the test file.
STEP 3.10Generate an HTML test report
python3 -m pytest tests/test_portal.py -v --headed --html=tests/test-report.html --self-contained-html
✓ Expected: tests/test-report.html created. Open it in a browser to see passed/failed tests with screenshots of failures.
NOTEIf pytest-html is not installed, run this first
uv tool install pytest-html

Code Review Agent — HTML, JS, CSS Quality Audit
The Code Review Agent reads AISymposium.html and produces a structured review covering code quality, security (XSS, input validation), accessibility (ARIA, contrast), and performance. It suggests specific fixes with code snippets.
14 min bmad-code-review
OPENOpen a brand-new Claude Code context window (Ctrl+N / Cmd+N)
/bmad-code-review
PASTECopy and paste this prompt. Press Enter.
You are the BMad Code Review Agent. Read AISymposium.html from the current directory. Read: AISymposium.html Perform a thorough code review of the AI Symposium Portal. Focus on these 5 areas: 1. SECURITY (Critical Priority) - XSS: Are user inputs sanitized before rendering to DOM? Check any innerHTML usage. - Authentication: Is the admin login logic secure enough for a demo? Are credentials hardcoded in JS? - Input validation: Are form fields validated before submission? - Check for any eval() usage, inline event handlers with user data, or unsafe DOM operations. 2. HTML QUALITY (High Priority) - Semantic HTML: Are heading levels correct (h1 → h2 → h3)? Are landmark elements used (nav, main, section, article)? - Form accessibility: Do all inputs have associated <label> elements? - Meta tags: title, viewport meta present? - Alt text: Do images/placeholders have descriptive alt attributes? 3. JAVASCRIPT QUALITY (High Priority) - Are global variables avoided (use const/let, not var)? - Is event delegation used efficiently? - Are there memory leaks (event listeners not removed)? - Is the navigate() function safe from hash injection? - Is the chat widget input sanitized? 4. CSS QUALITY (Medium Priority) - Are CSS custom properties used consistently? - Is there any hardcoded colour that should be a token? - Does the CSS handle both light and dark themes correctly? - Any unused CSS rules? 5. ACCESSIBILITY (Medium Priority) - Color contrast: Do foreground/background pairs meet WCAG AA (4.5:1)? - Keyboard navigation: Can the navbar and forms be used without a mouse? - ARIA: Is role="dialog" used for modals? Is aria-label on icon-only buttons? - Focus management: Does focus move into a modal when opened? For each finding, provide: - Severity: Critical | High | Medium | Low - Location: describe where in the file (function name or section) - Problem: what is wrong - Fix: exact code change to make At the end, produce a summary score (0–10) for each area and an overall portal quality score. Save as: code-review.md
SAVEReview and apply critical fixes
After code-review.md is saved, address all Critical and High findings by asking the Dev agent in a new context window to patch AISymposium.html. Keep a note of Medium/Low items for the next development sprint.
